# Mikit 多 SVN 目标目录同步设计

## 目标

让 `mikit sync-svn` 能把同一套构建后的 CSS 同步到多个 SVN 工作副本目录，同时保持现有单目录项目配置可用。

## 方案比较

### 方案 A：新增 `targets` 数组并兼容旧 `target`（采用）

```json
{
  "syncSvn": {
    "source": "dist/css",
    "targets": [
      "F:\\SVN\\项目A\\view\\css",
      "F:\\SVN\\项目B\\view\\css"
    ],
    "files": ["*"]
  }
}
```

优点：配置含义明确；旧项目仍可继续使用字符串 `target`；未来可直接增加目录。缺点：需要同时维护单数和复数两个字段的校验。

### 方案 B：让原 `target` 同时接受字符串或数组

优点：字段数量少。缺点：同一个字段存在两种类型，配置可读性和错误提示较弱。

### 方案 C：每个目标配置独立文件规则

优点：每个 SVN 目录可复制不同 CSS。缺点：超出本次“同一套 CSS 复制到多个目录”的需求，配置复杂度更高。

本次采用方案 A。

## 配置兼容规则

- 新配置使用非空字符串数组 `mikit.syncSvn.targets`。
- 旧配置 `mikit.syncSvn.target` 继续支持非空字符串。
- `target` 和 `targets` 二选一；两者同时配置时报错，避免静默忽略其中一个字段。
- `targets` 不允许空数组、空字符串或非字符串成员。
- 重复目录按解析后的绝对路径去重，避免同一目录重复复制和重复计数。
- `mikit init` 默认生成 `targets: []`，由用户填写一个或多个 SVN CSS 目录。

## 同步行为

1. 从 `source` 第一层按 `files` 规则选择 CSS，保持当前通配规则不变。
2. 在复制任何文件前，先解析并校验全部目标目录均已存在且为目录。
3. 任一目标配置无效时立即报错，不向任何目标开始复制。
4. 对每个目标目录逐文件比较 SHA-256：内容相同计为跳过，不同则复制并再次校验。
5. 不创建目标目录，不删除目标文件，不运行 `svn add`、`svn commit` 或其他 SVN 命令。

## 返回值与命令输出

`syncCssToSvn()` 返回：

```js
{
  copied,
  skipped,
  files,
  source,
  targets
}
```

- `copied` 和 `skipped` 是所有目标目录的文件操作合计。
- `targets` 是去重后的绝对目标目录数组。
- 为保持内部调用兼容，继续返回 `target`（取第一个目标目录），并新增完整的 `targets` 数组。
- CLI 输出增加目标目录数量，例如：`完成：目标 2 个，更新 3 个，跳过 1 个。`

## 初始化和文档

- `mikit init` 生成：

```json
"syncSvn": {
  "source": "dist/css",
  "targets": [],
  "files": ["*"]
}
```

- README 同时展示多目录 `targets` 和旧版单目录 `target` 的兼容写法。
- README 说明所有目标会同步同一套 `source` 与 `files`，以及计数是跨目标累计值。

## 测试范围

- 单元工作流测试：两个目标分别收到相同 CSS；其中一个已有相同文件时正确累计复制和跳过数。
- 向后兼容测试：旧 `target` 字符串仍能同步。
- 配置校验测试：空 `targets`、非法成员、目标不存在、同时配置 `target`/`targets` 均报错。
- 原子校验测试：后一个目标不存在时，第一个目标不应收到文件。
- CLI 测试：输出目标数量和累计复制/跳过数。
- 初始化测试：生成 `targets: []`。
- 完整执行 `npm test`、语法检查和 `git diff --check`。
