# 动态字体分析与主动补字

在用户已要求字体打包、配置或修复缺字时使用。先分析网站项目，再执行已有 Mikit 命令；不要只把报告中的数字提示转交给用户。

## 先确认展示内容和实际字体

1. 阅读源码中的 HTML/SHTML、Vue 绑定、相关 JavaScript 和 CSS，沿可见文字的绑定路径检查数据来源、计算和格式化逻辑。
2. 将文字归属到实际 CSS font-family，检查继承、条件 class/style、font-weight 和 font-style。记录能支持判断的页面、表达式和代码位置。不能仅凭变量名含 count、price 或 time 就断言它一定显示数字。
3. 区分有限的源码文案与未来会变化的数值。源码可解析的固定数组、固定价格和条件文字由 CLI 自动提取，不需要为了它们额外补齐全部数字。

## 有明确依据时主动维护自动补字

用户已授权字体工作，且源码明确显示倒计时、计数、积分、数量或其他可变数值，同时字体归属可确定时，主动把缺少的数字字符补进 package.json > mikit > font > generatedFamilyExtraText，不再让用户重复确认这些已确定的信息。

- 可变整数：给实际使用的字体族补充 0123456789；不要只补当前报告缺少的几位，因为下次采集可能显示不同数字。
- 小数、百分比、负数、倒计时分隔符和单位：仅依据实际格式化代码或明确模板添加。例如 toFixed(2) 的小数点、模板中的 %、格式 HH:mm:ss 的冒号。单位也只添加源码或用户明确给出的文字。
- 固定数值和非数字动态文案：保留自动提取结果；不要仅因出现动态绑定就补数字。
- 保留用户的 familyExtraText、globalExtraText、页面地址和 ASCII 策略。Skill 推导的补字仅写入 generatedFamilyExtraText，按 Unicode 字符去重；已有 common/full 或用户显式补字已覆盖时不重复添加。
- 使用 CSS 字体族名作为键，不使用字体文件名或报告中的“字体族 / 700 normal”。补字目前按字体族生效，会分配给同族各字重和样式，可能使原本零字符的字体也保留。不要声称能按单独字重配置补字。
- 优先精确补字；不把全局 asciiBaseline 改成 common/full，不给所有字体补同一份数字，不用 globalExtraText 掩盖字体归属不明的问题。

示例：源码已确认 ActivityNumber 字体显示可变数量。将自动补字写入下面字段，保留用户的 familyExtraText 和其他配置；该族已有自动补字按后面的更新规则核对：

```json
{
  "mikit": {
    "font": {
      "generatedFamilyExtraText": {
        "ActivityNumber": "0123456789"
      }
    }
  }
}
```

示例字体族名不能直接写入实际项目，必须使用已检查的 CSS 名称。修改前简短说明证据和将补充的字符，随后在已授权范围内完成修改；用户明确要求仅分析或限制自动修改时遵守该限制。

## 后续修改与过期补字

每次字体任务都读取当前源码以及 familyExtraText、generatedFamilyExtraText，不能依赖历史对话来判断归属。familyExtraText 全部视为用户维护；即使以前由 Skill 写入，也不能自动迁移、认领或删除。generatedFamilyExtraText 是交给 Skill 维护的自动补字；用户要求长期保留的文案应放在 familyExtraText 中。

- 完整核对目标字体族在所有相关页面、共享模板、脚本、样式和条件状态中的用途后，重新计算仍需显式补充的字符，更新该族的自动补字。确认所有相关用途都已移除的字符可删除；该族没有剩余自动补字时移除其键。页面可直接提取的固定文字交给 CLI 采集，不要继续把它们作为过期补字保留。
- 只检查了局部页面、依赖缺失、接口文案范围未知或仍存在无法核对的用途时，只合并有依据的新增字符，保留无法确认过期的自动字符和未检查字体族，说明尚未完成清理。不能仅凭当前页面没出现、一次浏览器采集没显示或报告未列出就删除。
- 例如自动补字原为 abc，已完整核对并确认旧用途全部移除，新用途需要显式补充固定字符 1723，则更新为 1723；若 1723 已可由 CLI 直接采集，则无需保留该自动补字键；若新用途是可变整数，则更新为 0123456789。
- 用户补字与自动补字即使重合也保留各自归属。清理自动字段不改动用户字段；Mikit 合并去重后仍会保留用户补字、其他页面采集到的字符和配置的 ASCII 基线。直接运行 CLI 不会替 Skill 更新或清理配置。
- 写入前简要列出自动补字的新增、移除及依据，写入后检查 package.json 差异，确认用户字段保持原样。重复分析相同源码不应产生配置变化。旧项目未配置新字段时使用空对象，不迁移旧补字。

## 信息不足时再询问

以下情况先向用户明确提出缺少的信息，不猜测：

- 接口任意字符串、用户输入、无法确定的拼接结果，或动态内容类型不明：询问实际可能显示的文案或范围。
- 字体族归属不明：说明对应页面和绑定，需要用户提供字体或可复现状态。
- 需要浏览器采集但缺少完整页面地址：询问完整 HTTP/HTTPS URL，包含主机、端口和所需状态；源码中的候选路径只能作为提问依据。

已有用户提供或项目配置的完整 URL 可以核对后复用，不重复询问。不猜测查询参数、登录状态、点击序列、等待选择器或浏览器路径。mikit.font.pages 用于运行时 DOM 采集；--font-page 只覆盖静态页面范围，两者不能替代。仅为确定的数字补字时，不必强制用户提供动态 URL。

## 执行并闭环验证

1. 配置写入后解析 package.json，检查聚焦差异，确认已有内容保留。已有构建输出时，按网站项目既有调用方式运行 mikit font；不因此擅自重建整个网站、启动常驻服务或发布。
2. 打开命令打印的报告路径，默认 font/font-report.md。核对顶部字体表、“待处理事项”和“采集详情”，检查字符来源、TXT 和输出格式。新报告的“动态字体配置示例”提供面向用户手动配置的 JSON；Skill 推导的补字应写入 generatedFamilyExtraText，不能照搬到 familyExtraText。示例 URL、字体族及文案占位内容必须替换，不能原样自动写入项目。
3. 如果报告出现数字提示，回到对应源码核对；已有明确证据则完成精确补字并重跑。没有新证据或配置变化时，不反复执行来试图消除提示。
4. 同族多字重分别核对清单；显式按族补字导致字符重合是预期行为。检查源码字体支持的请求字符是否覆盖，输出格式是否符合当前 CSS 引用；源字体缺字需要更换或回退字体，追加文本不能解决。
5. 动态页面仅覆盖实际访问到的 DOM 状态。无法复现的状态、未提供的接口文案及未执行的验证必须如实报告，不能把“生成成功”描述成所有未来文案均已覆盖。
6. 最终简要说明自动补字新增和移除了哪些字体和字符、依据是什么、验证结果，以及仍需用户提供的内容或尚未确认可清理的旧补字。直接调用 CLI 仍按配置执行，Skill 的主动分析不代表 CLI 自动修改配置。
